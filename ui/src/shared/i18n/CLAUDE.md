# Language

The phrase catalogue, how a translation reaches it, and the `Intl` formatters that follow it. `ARCHITECTURE.md` has why the catalogue lives in `shared/` and what the build emits.

**Every phrase a person can read goes through `t()`.** A string literal in JSX is a phrase that will never be translated, and nothing catches it. The exceptions are what the *player* answers with: a track's title, a playlist's name or a genre tag, which are the user's own data and are never Jean's to reword.

**Names of things outside Jean stay in the language they are in.** `PANE` in `TagWriting.tsx` is a menu path inside foobar2000, `Library → Search` is another, and `"Fields they may write"` is `foo_jean`'s own label: those are strings somebody has to find on a screen that is in English whatever Jean is showing. Translating them sends the reader looking for a menu that is not there.

## Writing a phrase

**Keys are flat, dotted and sorted**, so a translator can diff `en.json` between two releases and see exactly what to write. The prefix names the area, not the file.

**A phrase whose key is chosen at runtime MUST be typed narrower than `Phrase`.** `t()` derives its argument list from the key, so a parameter typed as the whole union demands the union of every phrase's fields and every call becomes "Expected 2 arguments". The answer is a template-literal `Extract` beside the thing that holds the key, so `ShortcutName`, `ColumnLabel` and `DetailPhrase` also stop a binding pointing at an unrelated phrase. **Keep the families that take fields out of those unions**: `shelf.plays` takes a `count`, so `ShelfPhrase` names titles and blurbs and not the whole `shelf.` prefix.

**A sentence with something drawn inside it is one phrase, not three.** `<Trans>` splits the resolved string on its fields and puts a node in each, so word order stays the translator's. Cutting the sentence up in JSX fixes English word order into every language.

**Pluralise through the catalogue, never in code.** A value written as an object is selected by `Intl.PluralRules` on `count`; `other` is the only form every language has and is the only one required. English needs two forms and Polish needs four, so `count === 1 ? a : b` at a call site is a rule that is wrong outside English.

## Loading

**English is bundled and every other language is fetched.** `en.ts` is the fallback layer, so a stock install costs no request, and a file on disk can never break the language the app falls back to. `locales/en.json` is generated by the build **as the file to copy** and is never read at runtime, so editing it changes nothing, which is what the Settings help says.

**Jean cannot list its own folder.** beefweb's static server serves no index, and `/api/browser/entries` is refused for anything outside the player's music directories. So the shipped codes are compiled in from `public/locales/` and anything else is named by hand in `locales/custom.json`. **Nothing writes that file.** That is what stops a new build copied over an old one from erasing somebody's languages, and it is why the file the build owns and the file the reader owns are two different files.

**A stock install has no `custom.json` and the 404 is the answer.** Never report it.

**Boot resolves the language before the first render**, so nothing paints in English and then changes. The custom list is fetched only when this device has no stored choice to honour, since that is the only time negotiation needs it.

**A missing key falls back to English and a key Jean no longer has is dropped.** A translation written against an older release stays usable, and a half-finished one is usable from its first line. Settings names the count rather than leaving it to be noticed.

## Formatting

**A figure follows the words beside it.** `useFormats()` returns the `Intl` bundle for whatever language is showing; `toLocaleString()` and a bare `new Intl.…` follow the *browser*, which is a different language the moment somebody picks one. Every formatter is memoised, because they are built per row of a virtualised list.

**Sorting and grouping go through `collatorIn`.** A `<` on two strings is not an alphabet.

**A language is named in itself and never by a flag.** `nameOfLanguage` asks `Intl.DisplayNames` in the language's own locale, so somebody who cannot read the current interface can still find their row. One flag stands for several languages and several countries share one language; there is nothing to draw.

## Traps

**`en.ts` imports nothing, and adding an import breaks the build.** `scripts/localePlugin.ts` reads it under Node's resolution to generate `en.json`, where a relative specifier needs a file extension that the app's own scope refuses. `messageFor` in `locale.ts` is what typechecks its values against `Message`.

**Anything that puts a phrase into data a `useMemo` holds MUST take the translator as an argument.** `translate` reads the current catalogue through a module no caller can see, so a helper that reaches for it hides a dependency the memo above it will not have, and the phrase stays in the language the reader just left until unrelated data changes. Passed in, the linter asks for `t` in the dependency array and the whole class of staleness is a compile-time question. `Translate` lives in `locale.ts` rather than beside the hook, so a module compiled in the spec scope, where React is not, can still name it.

**The corollary is that derived data holds no display fallback.** An album with no artist tag carries `null` and the renderer supplies the phrase: what to call an untagged record is a phrase, and one baked into a growing index would be the language that index was first built in for as long as it lives.

**`useTranslate()` returns a fresh function whenever the language changes, and that is the point.** A memo keyed on a stable function goes on showing the old language. The dependency on the locale state exists to *fire* the memo and is not read inside it, which is what the suppression there says.

**A leaf drawn once per row reads the module-level `translate()` instead.** `Stars` and `ActionMenu` are on the virtualised path, where a `useSyncExternalStore` per cell costs more than a label that updates on the next render is worth.

**A keyboard shortcut is not translated, and `shared/keyboard/CLAUDE.md` has what follows from that for the label beside it.**

**`fold()` already strips diacritics**, so a translated label stays findable in the command palette without anything extra.
